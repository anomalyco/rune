- Windows DX12: honour `WGPU_DX12_PRESENTATION_SYSTEM` (`visual` / `hwnd`) and automatically fall back from DirectComposition (`DxgiFromVisual`) to a plain HWND DXGI swap chain (`DxgiFromHwnd`) when DirectComposition itself is unavailable (`CreateSwapChainForComposition` returns `E_NOTIMPL`, or `dcomp.dll` / `DCompositionCreateDevice2` / `CreateTargetForHwnd` fails on a live device), keeping the first adapter instead of walking remaining adapters on the broken DirectComposition path; real Windows machines with working DirectComposition take the exact previous path with no extra launch work. Windows on the plain HWND fallback are opaque only (transparent windows degrade to opaque), cannot use DirectComposition video layers (falling back to UI-drawn video), transition directly to `SurfaceMode::Gpu` without seamless visual commit or the NVIDIA G-SYNC premultiplied VRR guard, and Windows overlays (`App::overlay`) continue to fail cleanly because they require DirectComposition. Compiled and verified with off-screen unit tests; not run live under Wine or Proton.
