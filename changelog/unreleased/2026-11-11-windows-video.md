- **Windows: `Player` plays video and audio with Media Foundation.** Each clip decodes on a thread of its own with the source reader, on the GPU's decoder where the adapter has one (DXVA through a D3D11 device on Rune's adapter) and in software otherwise; pictures go through a small ring of shared NV12 textures that Rune's D3D12 device samples in place (`with_plane_slice`), so no picture crosses the CPU. The player is one explicit machine (idle, opening, buffering, playing, paused, ended, failed); the UI thread swaps in the picture for the refresh the frame presents at (DWM's timing) and asks for its next frame only when the next picture is due. Clips loop without a gap, an undrawn clip stops decoding and lets go of its decoder after 3 s, and sound plays through WASAPI on the clock. Media Foundation, D3D11 and WASAPI load on the first clip through `GetProcAddress`, so launch loads nothing new and the import table gains nothing. `RUNE_VIDEO_LOG=1|frames` prints each open's steps and frames in microseconds; `RUNE_VIDEO_DECODE=software` skips the GPU decoder. `Player::set_volume` and `volume` set the sound's gain, on macOS too.
- **Native surfaces: GPU timestamps only for observed surfaces, and a new picture reuses its draw's buffer.** Render-pass timestamp queries now run only while a drawn surface has an observer (`set_observer`), and a draw whose picture changes keeps its uniform buffer and up to 8 bind groups for textures it showed before, so a playing video allocates nothing per frame.
- **Window pacing: motion's own frames come when due on a host with no display link.** A loop's next step or a video's next picture no longer waits a frame interval after the last poll, which drifted later every frame and dropped a picture about every half second; poll timers keep that floor.
