- **A quit is one explicit machine, and a Windows logoff runs `App::on_quit` even with a menu open.** `crate::quit`'s `State` (running, quitting with the windows' hooks owed or run, closed for a session's end, done) and its `step` replace the quitting flag and quit counters. `Tx::quit` and `AppHandle::quit` mark the app quitting before the loop exits, so a window closing later in that turn closes for the quit (`rune::quitting`). The right-click window menu opens from a posted message, as pop-up menus do, so its modal loop runs outside the loop's handlers: a `WM_QUERYENDSESSION` while it tracks runs every window's hook, and the windows' timers keep turning while it shows. A session message that still comes while a handler runs ends the tracking menu and answers without running the loop (which would have re-entered winit's handler on a paint), and the hooks run as the handler returns.
