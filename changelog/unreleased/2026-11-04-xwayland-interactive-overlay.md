- **Interactive overlays can opt in to XWayland on GNOME Wayland.** `OverlayOptions::xwayland_input` (off by default; `OverlayHandle::set_xwayland_input` changes it before a show) lets an overlay that takes the pointer show on XWayland when the compositor has no layer-shell. It opens as the same override-redirect ARGB window, with an input shape covering the whole window or its hit regions, and reads its own pointer events (move, enter, leave, primary and secondary buttons). Being override-redirect, it never takes keyboard focus; `KeyPolicy::OnDemand` overlays still can't use it. Connecting starts XWayland on GNOME, so the host decides, having checked it already runs. Without the opt-in nothing changes.
