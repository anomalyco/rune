- **macOS: work a failed Metal command buffer discarded never reads as finished on a stock wgpu Metal device.** The vendored wgpu-hal set the loss in one place and advanced the fence in another, so a fence read between the two, or a handler that ran out of order, could report a failed submission finished (its `on_submitted_work_done` callback running) before the loss showed. It now takes wgpu's fence: every command buffer of a submission counts towards it, a submission finishes only once all of them, and every earlier one, have, and a failure sets the loss in the same lock as the fence's advance (gfx-rs/wgpu#10570, merged, and the fence part of #10875).
