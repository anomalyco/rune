- `rune-notify` posts on Linux through the desktop's notification server (`org.freedesktop.Notifications` on the session bus), where `available` was false and every call did nothing: posting an id again replaces its notification, `remove` closes it, notifications stay silent (`suppress-sound`), buttons post where the server shows actions, and a click reaches `on_click` with the posted id and user info while the app runs, plus the server's XDG activation token in the new `Click::activation_token`. `register` names the app and its desktop entry. Text boxes (`Notification::reply`) are left out on Linux; the XDG portal (`org.freedesktop.portal.Notification`) is not used yet, so a sandboxed app needs permission to talk to `org.freedesktop.Notifications`. The first `available`, `post` or `remove` waits up to about 2.5 s to connect: make it after the first frame (`on_ready`).
