- macOS: native child `NSView`s added to a window's content view (for example an embedded `WKWebView` via `WindowHandle::with_raw_handle`) are now exposed to VoiceOver and Accessibility hit-testing alongside Rune's AccessKit tree. `vendor/accesskit_macos`'s subclassing adapter merges `[super accessibilityChildren]`, checks native subviews first in `accessibilityHitTest:` (falling through to AccessKit when AppKit hits only the content view or its ancestors), and forwards `accessibilityFocusedUIElement` when the window's first responder is a descendant native `NSView`. Rune's internal `RuneMaterialHost` backdrop view is explicitly hidden from AppKit accessibility so system materials do not appear in VoiceOver or capture hit tests.
