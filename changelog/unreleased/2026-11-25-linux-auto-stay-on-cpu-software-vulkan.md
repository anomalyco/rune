- **Linux `CpuFirst::Auto` stays on `CpuPainter` when the GPU is a software one:** with `WGPU_ADAPTER_NAME` unset, an opaque window that opened on the CPU still makes its GPU on a thread after the first frame, but when that device's adapter is `wgpu::DeviceType::Cpu` (Mesa lavapipe, llvmpipe) the window no longer hands over to it: it stays on `CpuPainter` (`gpu.window.software_deferred`), the thread skips the window's warm frame, and the device lapses from the warm slot after 30 s. A frame that later needs a GPU-only feature (`NeedsGpu`) starts or takes the software GPU and hands over, keeping the previous frame until the GPU draws (no degraded fallback paint on Linux yet). Hardware GPUs, pinned `WGPU_ADAPTER_NAME` adapters, `CpuFirst::Only`, `CpuFirst::Off`, transparent windows and second windows are unchanged; restore the hand-over to the software GPU with `App::cpu_first(CpuFirst::Off)`, `RUNE_CPU_FIRST=0` or `WGPU_ADAPTER_NAME`. Not measured on lavapipe or a live GPU-less desktop. Refs #2068.
