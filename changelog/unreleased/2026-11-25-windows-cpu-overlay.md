- Windows overlays: added opt-in `RendererKind` (`Gpu`, `Cpu`), `ConfiguredOverlay::renderer(kind)` (default `RendererKind::Gpu`), memo-tracked `Cx::renderer_kind()`, and `Runtime::set_renderer_kind` (wired into both overlays and desktop `CpuFirst` windows). On Windows, `ConfiguredOverlay::renderer(RendererKind::Cpu)` keeps a transparent overlay on `CpuPainter` for its lifetime and presents premultiplied BGRA frames (`clear = [0.0; 4]`, `lcd = false`) through documented Win32 `UpdateLayeredWindowIndirect` (`ULW_ALPHA`) without creating a GPU device or swap chain, paced with `PollPace` + `DwmGetCompositionTimingInfo`, with fade-out via `SourceConstantAlpha`, DIB memory freed on hide, graceful `NeedsGpu` degradation/hold, refusal of `WindowBackdrop` and Windows `El::system_material` host backdrop visuals, and one-shot fallback to GPU if layered setup fails; non-Windows targets ignore `RendererKind::Cpu` cleanly and stay on GPU (`examples/overlay-lab` adds an opt-in `--cpu` flag).
