- Tooling: a `--trace` run no longer writes its trace file from the thread that draws. Each line goes over a channel to a `rune-trace` thread that owns the file and writes it as it arrives, so a frame can no longer wait on the disk: written from the frame's own thread (about 5 KiB a frame through an 8 KiB buffer, a write call every frame or two), a line waited 60 to 220 ms on the growing file's lock in recorded runs on Windows, and the trace then showed a frame gap the app did not have. The end of a `--frames N` run now waits for the file, so it holds all `N` frames (a fast exit dropped the buffer's tail: traces of 1,000 frames held 988 to 999); a process that dies loses only the lines the thread had not written yet. No trace, no thread: the thread starts in `Trace::open`.
