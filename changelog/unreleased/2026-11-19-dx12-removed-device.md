- **Windows: a GPU reset or a removed GPU reads as a lost device, never as finished work.** A removed D3D12 device's fences read `UINT64_MAX`, which wgpu-hal returned as every submission done: each pending completion callback (a video frame's, a readback's) fired as if its work had run, and the device-lost callback never ran. The vendored wgpu-hal (`vendor/wgpu-hal.patch`, `Device::unless_removed`) now reports such a read as `DeviceError::Lost`. Rune's test that kept GPU work pending (`completion_worker_preserves_cpu_gpu_overlap`) sizes its workload from a short calibration and plans no submission over 100 ms, where a fixed 68.7 billion iterations ran past Windows' 2-second limit on an integrated GPU and reset it; it and the other GPU tests fail when their device is lost.
