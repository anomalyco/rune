- **Windows: a GPU reset or a removed GPU is seen as a lost device, never as finished work.** A removed D3D12 device's fences read `UINT64_MAX`, which wgpu-hal returned as every submission done: each pending completion callback (a video frame's, the CPU-to-GPU hand-over's) fired as if its work had run, and nothing marked the device lost until a later call failed. The vendored wgpu-hal (`vendor/wgpu-hal.patch`, `Device::reached`) now leaves a removed device's work pending, and `Gpu::is_lost` asks D3D12 itself (`rune_gpu::health::removed`), so the window replaces its device on the next frame. Rune's test that kept GPU work pending (`completion_worker_preserves_cpu_gpu_overlap`) sizes its workload from short timed submissions and plans none over 100 ms, where a fixed 68.7 billion iterations ran past Windows' 2-second limit on an integrated GPU and reset it; it and the other GPU tests fail when their device is lost.
