- **Windows: a click or key at the first frame no longer waits for the window's start-up work.** After its first frame a window ran the app's `on_ready`, its drop target and session-lock hooks, the GPU's start and the accessibility adapter in one turn: 30-50 ms the first input waited behind. They now run one piece a turn, and none while a key or mouse message waits. OpenCode, a click posted as the first frame showed: handled 41-58 ms after it before, 13-15 ms after (the rest is winit's keyboard-layout table, built by the first input).
