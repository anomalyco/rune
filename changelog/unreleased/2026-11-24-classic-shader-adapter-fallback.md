- **Fallible `Renderer::try_new` / `Renderer::try_with_springs` and adapter fallback on rejected shaders.** Building Rune's last-resort (Classic) uber shader, spring uber shader, or target-format pipeline now runs inside wgpu error scopes (validation, out-of-memory and internal, including on Rune's native Metal backend and asynchronously on browser WebGPU). When a picked adapter rejects the last-resort shader during window, overlay, handover or headless setup, Rune walks remaining adapters through the fallback chain (other hardware first, software/WARP last) and logs the fallback; adapters named via `WGPU_ADAPTER_NAME` are never replaced. When no adapter works, windows record `AppHandle::window_error()` and end `App::try_run()` / `App::run()` with the error, overlays report unavailability without taking the app down, headless runs exit non-zero, and web pages either fall back to the CPU 2D canvas or display the error instead of staying blank. `Renderer::new` and `Renderer::with_springs` remain as panicking wrappers over the fallible constructors.
