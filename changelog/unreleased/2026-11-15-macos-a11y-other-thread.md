- macOS: an accessibility read of Rune's own windows from another thread answers as the view would instead of aborting the app. AccessKit's macOS adapter borrowed main-thread state in `accessibilityChildren`, `accessibilityFocusedUIElement` and `accessibilityHitTest:` wherever AppKit asked, and a system-wide read such as `AXFocusedApplication` with one of Rune's windows key is answered in-process on the asking thread: a borrow in flight on the main thread panicked inside `extern "C"` and aborted the process. Off the main thread the vendored adapter now takes the view's own answer (`scripts/vendor-accesskit-macos.sh`).
