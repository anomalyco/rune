- **Hover no longer lights the wrong element for a frame after a commit.** A commit that inserts or removes elements before a hover group (a reply finishing above a queued prompt) shifted the node indices, and a hover pass during that commit read the last frame's drawn rects by those indices, so the group under the pointer's old target lit instantly and went dark the next frame. Every hover pass now waits for the frame's build when the indices moved, and the build re-evaluates keyboard-focus hover (`El::hover_group_focus`) too.
