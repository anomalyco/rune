- **Rune apps host Luau scripts that build their UI.** A new `rune-luau` crate runs one sandboxed Luau VM per `Script` (`mlua`, native code on Windows and Linux, the interpreter on macOS and the web) with a 250 ms watchdog. `ui.row(props, children)`, `ui.text(content, props)` and the other constructors are C functions that build `El`s straight into a per-render arena; `view:Memo` wraps `memo_with_hash`, so an unchanged subtree costs no Luau call, and `ui.virtualList` is `El::virtual_rows`, calling `renderRow` only for rows entering the window. `task.spawn`/`defer`/`delay`/`wait`/`cancel` run on the frame clock `poll` receives and on worker threads (`spawn_blocking`, `Completer`), so an idle script never enters its VM; `Signal`, `ScriptSignal` and `Connection` follow Roblox's `Connect`/`Once`/`Wait`. `require` follows Luau's require-by-string rules (`@self`, `.luaurc` aliases) inside the script's folder, `Script::reload` and the `watch` feature swap the VM in a few milliseconds keeping `saveHotState`, and a failing render shows an error card instead of panicking. `scripts/web-build.sh` builds such apps for the web when `WASI_SDK_PATH` points at WASI SDK. `examples/luau-panel` hosts a panel with a 1,000-row list; its `luau-bench` measures the performance gates.
