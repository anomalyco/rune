- **Windows: a frame only a loop asked for runs the loop alone.** When nothing reached the window since its last frame (no input, wake, timer, request or other motion) and every loop on screen is one a step can draw, the frame samples the loops into the instances they drew and nothing else runs: no `poll`, view, layout, paint or instance diff. Only those instances are uploaded, only the pixels they cover are redrawn (with only the instances that reach them), and only those are presented. Two kinds of loop qualify: a spinner's dots (an opacity cycle on a plain fill, as the web already did), and a window sliding sideways over content that slides back inside it, as a text shimmer is made (`clip_fade` on a `LoopSpec::slide` whose only child slides the other way): a step moves only the window's clip and soft edges. Anything else on screen, a slide up or down, a step that would show or hide a node or a glyph, or the first frame of a new swap chain takes an ordinary frame. On Windows, such a window's own edges glide between pixels instead of stepping one pixel at a time (what it holds still snaps); every other slide, and every slide on other platforms, snaps as before. An app's `poll` no longer runs on frames only a loop asked for: work it does on a timer asks for one (`Tx::wake_after`).
- **`RUNE_LOOP_CHECK=1` in a headless run** (`--frames`, any platform) asks for a loop-only step before every frame and compares it with the ordinary frame that runs instead: the run ends with how many steps differed and why the others wouldn't step (`RUNE_LOOP_CHECK_LOG=<file>`: one line per frame).
