- **Windows: a frame only a loop asked for runs the loop alone.** When nothing reached the window since its last frame (no input, wake, timer, request or other motion) and every loop on screen is one a step can draw, the frame samples the loops into the instances they drew and nothing else runs: no `poll`, view, layout, paint or instance diff. Only those instances are uploaded, only the pixels they cover are redrawn (with only the instances that reach them), and only those are presented. Two kinds of loop qualify: a spinner's dots (an opacity cycle on a plain fill, as the web already did), and a window sliding sideways over content that slides back inside it, as a text shimmer is made (`clip_fade` on a `LoopSpec::slide` whose only child slides the other way): a step moves only the window's clip and soft edges, posed from an anchor rect kept across paints, so a step and an ordinary frame reach the same numbers. Anything else on screen, a slide up or down, or a step that would show or hide a node or a glyph takes an ordinary frame, and the first frame on a new swap chain (any surface configure) draws whole. On Windows, such a window's own edges glide between pixels instead of stepping one pixel at a time (what it holds still snaps); every other slide, and every slide on other platforms, snaps as before. An app's `poll` no longer runs on frames only a loop asked for: work it does on a timer asks for one (`Tx::wake_after`).
- **`RUNE_LOOP_CHECK=1` in a headless run** (`--frames`, any platform) asks for a loop-only step before every frame and compares the instances it would write with the ordinary frame's: the run ends with how many steps were compared and differed, and why the others wouldn't step, and fails (exit 3) when it compared none or any differed (`RUNE_LOOP_CHECK_LOG=<file>`: one line per frame). `RUNE_LOOP_CHECK=2` (Windows, a window) compares pixels instead: each loop-only frame's kept picture against the same instances drawn whole, and exits 3 at the window's close if any differed.
