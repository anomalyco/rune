- **Windows: a frame only a loop asked for runs the loop alone.** When nothing reached the window since its last frame (no input, wake, timer, request or other motion) and every loop on screen is one a step can draw, the frame samples the loops into the instances they drew and nothing else runs: no `poll`, view, layout, paint or instance diff. Only those instances are uploaded, only the pixels they cover are redrawn (with only the instances that reach them), and only those are presented. Two kinds of loop qualify: a spinner's dots (an opacity cycle on a plain fill, as the web already did), and a sliding window over content that slides back inside it, as a text shimmer is made (`clip_fade` on a `LoopSpec::slide` whose only child slides the other way): a step moves only the window's clip and soft edges. Anything else on screen, or a step that would show or hide a node or a glyph, takes an ordinary frame. A sliding loop's own edges now glide between pixels instead of stepping one pixel at a time; what it holds still snaps to the grid. An app's `poll` no longer runs on frames only a loop asked for: work it does on a timer asks for one (`Tx::wake_after`).
