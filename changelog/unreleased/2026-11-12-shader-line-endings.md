- **Windows: the precompiled uber shader is used whatever a checkout's line endings are, and a launch no longer works out whether it matches.** A clone made with Git for Windows' `core.autocrlf=true` has CRLF in its `.wgsl` files, so the WGSL never hashed as the DX12 bytecode recorded and every launch compiled the shader with FXC (10 to 13 s before the GPU drew). Rune's new `build.rs` joins the uber shader's WGSL (Classic, and Windfoil with outline.wgsl) once, reading `\r\n` as `\n`, and hashes it, and the pipeline layout's fingerprint is a `const fn`, so the text and the decision are constants: a launch builds, formats and hashes nothing to choose the bytecode (Windows and macOS, for the DXBC and both metallibs; the recorded layout hashes are the new fingerprint's). A `.gitattributes` keeps the WGSL and the other text Rune compiles in at LF in new checkouts. A stale precompiled shader is a build warning naming the command that rebuilds it, and a launch that can't use the DX12 bytecode says why once. Classic renderers on Windows no longer check Windfoil's bytecode, which could never match them. `examples/regenerate_dxbc.rs`, which hashed the wrong variant, is gone: `cargo run -p rune --example regen_dxbc` regenerates the bytecode.
