- **Windows: a frame redraws and presents only what changed.** The renderer keeps the window's last frame (`render::damaged`), redraws into it only the rectangles whose instances changed (at most four; the lists' common start and end skipped, and instances in both lists unchanged wherever they moved to), copies it to the drawable and presents those rectangles alone (`Present1` dirty rectangles; vendored wgpu-hal now makes flip-sequential swap chains and has `Surface::set_present_rects`). A frame with an effect slot, backdrop blur, GPU springs, a native surface, or a turned or blurred layer draws whole, as does one that changed most of the window. Typing in OpenCode's composer at 1350x900 on a 240 Hz Iris Xe: GPU per key frame 4,830 µs before, 890 after; input to photon 12,318-13,836 µs p50 before, 7,782 after, shown at the second refresh after the key for 69 of 80 keys (a bare D3D11 window: 4,686); the screen after a run of partial frames is the same, pixel for pixel, as after the same run drawn whole.
