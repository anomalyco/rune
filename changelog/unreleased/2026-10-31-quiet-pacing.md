- **A timer frame that draws nothing new no longer starts the display link, and overlays skip it too.** A resting window's timer frame used to start the macOS display link before finding it would draw what was on screen, then stop it again: a link start and stop on every wake. It now builds the frame first when the stopped link would draw at once anyway, and starts the link only when the frame draws. Overlays had no such skip: every `wake_after` presented a full frame, even when `poll` returned false. A resting overlay's timer frame now builds before taking a drawable and presents nothing when its pixels match the last frame. For a 30 Hz `wake_after` that changes nothing on screen, an overlay went from about 19 presents a second and 4.6% CPU to none and 0.7%. Frames that draw (motion, input, a wake that changes something, live resize) are paced as before.
