- Memory (Linux/glibc): Rune now calls `malloc_trim(0)` once off the UI thread after a window or overlay finishes resting on Linux with glibc so freed heap pages return to `VmRSS`; opt out with `App::trim_heap_at_rest(false)` or `RUNE_MALLOC_TRIM=0`. The trim is coalesced across concurrent rests with a 30 s cooldown (never on a periodic idle timer), skips automatically via a runtime `mallinfo2`/`mallinfo` probe when the process uses a custom `#[global_allocator]` or `LD_PRELOAD` allocator, and compiles to nothing off Linux/glibc. Because glibc locks each arena while trimming it, a thread allocating in the same arena during the trim can pause for ~7 ms on a ~206 MiB freed heap and ~14 ms on a ~387 MiB freed heap (exceeding an 8.3 ms 120 Hz frame), so apps with allocating real-time threads should opt out.
