- **Quitting hides every window first, and `rune::fast_exit` ends the process without teardown.** A quit (`Tx::quit`, the last window closing, the OS ending the app) hides every window and overlay before any `App::on_quit` runs, and a window's close hides it before its `on_close`, so the window is gone the moment the user asks and the hooks run unseen; a Windows session query, which another app can still cancel, leaves the windows up. `rune::fast_exit(last)`, set before the app runs, then skips dropping the windows, the GPU devices and every allocation: once the hooks ran, the clipboard hands over what it holds, tray icons leave the notification area, a relaunch starts, `last` runs (the app's final durable write, a trace) and the process ends with `TerminateProcess` on Windows and `_exit` elsewhere. Nothing after the event loop returns runs then, so whatever an app does there moves into `last`. A window on Windows measured 23,774 µs from its hooks to `run` returning and 716,472 µs more until the OS reported it gone; with `fast_exit`, 4 µs from the hooks to `TerminateProcess`, and the rest is the OS releasing the process (2,654 µs for a window with no GPU device, 20,194 µs with a device, 184,177 µs once a swap chain has presented, on an Iris Xe).
