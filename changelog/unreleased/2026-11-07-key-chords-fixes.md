- **Key chords and text fields follow each platform's keyboard.** Paste, copy, cut, select all, undo and redo in a text field take only the plain chord, so Ctrl+Alt+V, Ctrl+Shift+V and ⌃⌘C reach `on_key`; Ctrl+Y redoes off macOS. On Windows, characters typed with Left Ctrl + Left Alt (AltGr there, such as "@" on a German layout) insert instead of vanishing, and Home and End in a multi-line field move to the line's edge (Ctrl+Home and Ctrl+End to the text's ends). Off macOS, a chord on a key that types a non-ASCII character arrives as the US key in its place (Ctrl+М on a Russian layout is `Key::Command('v')`, as on macOS), so copy, paste, undo and app chords work on Cyrillic, Greek and other non-Latin layouts. `Chord::matches_tx` no longer treats a shifted symbol as its US key when the layout says otherwise, falls back to the physical key on Cyrillic, Greek and other non-Latin layouts, and matches "mod+plus" with the Shift that types "+". `Chord::new` stores its key as parsing would, "{" parses as Shift+[, "mod + +" parses, and `ChordKey` adds Print Screen, Scroll Lock and Pause. New: `Chord::matches_on`/`matches_tx_on`, `Keybind::matches_on`/`matches_tx_on`/`spec_on`/`on_chords`, `From<Chord>` for `Keybind`, and `Shortcut::parse_on`, which also takes `opt`, `win` and `plus`. `Keybind`'s `Display` writes the chords that apply on the current platform. On the web, `KeyPlatform::current()` reports `Mac` in a browser on an Apple device, and ⌃⌘B no longer matches "mod+b".
