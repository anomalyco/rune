- Tooling: `--window-script FILE.json` replays a script's input in a real window, on the wall clock from its first drawn frame: the same events `--script` takes, landed through the same `script_point` and `script_input` a headless run uses, so hover, drags and the wheel can be shown with the real compositor and frame clock on a desktop the system cursor never reaches (a harness's hidden desktop, where every posted move is followed by a leave). The window `--window KEY` names replays it, else the first window the app opens; it prints `rune-script-window KEY`, `rune-mark NAME T ELAPSED`, then `rune-script-done T ELAPSED`, or `rune-script-error T ELAPSED WHY` and stops (also when no frame is drawn within 10 s). The file is read and parsed with the arguments, so a broken one ends the run before any window. While it replays, the system's pointer events are dropped; keys, focus and resize still come from the system. A relaunch (`Tx::relaunch`) drops the flag: `rune::RELAUNCH_DROPS` lists every flag an app started again never carries over (today only `--window-script`), and `rune::without_relaunch_drops` strips them, so an updater that restarts the app itself uses Rune's list instead of its own. It cannot show the system's pointer messages and their DPI and delta scaling, the system cursor and its own hover tracking, the custom caption buttons, overlay windows, the low-level mouse hook and `press_point`, or an engine's native windows.
