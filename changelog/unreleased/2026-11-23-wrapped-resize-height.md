- **Windows: a resize with a wrapped negative client size no longer corrupts the surface, viewport or CPU frame buffer.** Windows can transiently report a negative client height wrapped to `u16` (such as `65527` in `WM_SIZE`) or `u32` (from `GetClientRect`), exceeding `max_texture_dimension_2d`. `Win::resize_surface` and the resize/scale handlers now ignore zero or out-of-range sizes and keep the previous drawable and viewport until a valid size arrives, and initial surface creation and reattach clamp to the device's texture limit (or `16384` during CPU boot before a GPU is attached).
