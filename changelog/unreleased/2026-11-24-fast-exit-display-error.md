- **Lost display connections now bypass fast exit so `try_run` returns the error and `run` prints it to stderr and exits 1.** Previously `Windows::exiting` called `end_fast` under the default fast-exit mode even after a Wayland or X11 display failure, terminating with exit code 0 before `event_loop.run_app` could return the error. Lost display connections now share the startup-error exit path, while normal quits stay fast.
