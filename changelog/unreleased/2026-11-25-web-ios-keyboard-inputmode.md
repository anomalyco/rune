- **Web: set `inputMode = 'text'` and clear `inert` before every hidden-input `focus()` call on coarse pointers.** On phones (where hidden inputs start as `inputMode = 'none'` so non-editable taps do not raise the keyboard), `bridge.js`'s `sync()` and startup microtask previously called `h.field.focus()` before flipping `inputMode` to `'text'`, causing iOS Safari to suppress the virtual keyboard at focus time. All three hidden-input focus sites (`mount` microtask, `sync()`, and `activate()`) now go through one `focusInput(h)` helper that sets `inert = false` and `inputMode = 'text'` before calling `focus()` while keeping `opacity: 0` (WebKit's native selection-UI suppression threshold) and resetting `inputMode = 'none'` and `inert = true` whenever no editable field is focused. In addition, `sync_input(false)` defers syncing the hidden input while a touch is still held down so a mid-tap `requestAnimationFrame` cannot steal focus outside the `touchend` user gesture.
