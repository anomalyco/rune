- `App::layout_seed(seed, keep)` (and `WindowSpec::layout_seed`): an app that keeps its window's state across launches can keep the view's layout reads too. A view that reads a rect (`Cx::layout`, `layout_with`, `layout_size`) got nothing in a window's first commit and ran a second time once layout knew it, so a desktop app's first frame built its whole first screen twice. `keep` is given a `LayoutSeed` (the rects the window's FIRST view read, with the viewport, scale and zoom: a first frame is drawn before a server or a plugin has answered, so its reads are what the next launch's first frame reads again) when the window rests, closes or quits; passed back at the next launch, the first view is given those rects and runs once when layout agrees with them (and at the seed's zoom from its first run). Every read is still checked against the layout, so a seed from another state costs what no seed costs, and one for another window size or scale isn't used. `RUNE_LAYOUT_SEED=log` prints each read a seed got wrong; the marks `layout.seed.held` and `layout.seed.moved` say which a launch was.
