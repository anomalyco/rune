- **Slow frames say where their time went, and whose it was.** With interaction timing on (Apple Silicon Macs), a watchdog thread samples the UI thread's stack while a frame runs past 12 ms (4 ms for a signature that was slow before), so a slow `ui.interaction` names the functions it spent its time in (`rune.hot.0`, `rune.stack`), and a slow frame no input caused (a timer, a poll, an animation) goes as `ui.frame`. Each says whose time it took (`rune.cause`): `cpu`, `blocked`, or `scheduler_wait` when the machine was too busy to run it, which the rollup counts apart (`rune.scheduler_wait`) and never blames on the app. `examples/slow_click` shows a sleeping Save (`blocked`) and a computing Sort (`cpu`, in `sort_settings`).
