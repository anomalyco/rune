- **Scroll commit warnings, `RUNE_COMMIT_BUDGET_MS` and `El::scroll_anchor`.** Debug builds warn once per source when something commits the view on most frames of a scroll, which a scroll itself never needs, and name it: `poll`, a handler with its element and where it was set (`on_hover`, `on_hover_change`, `on_pointer_move`, `on_layout`, `on_drawn_layout` and `on_visible_rows` now record their call site), or the `Cx::layout` / `Cx::window_layout` read that moved. They also warn when an app steps a viewport with an instant scroll on 8 committing frames in a row, and when one hover handler commits for 8 different elements. `RUNE_COMMIT_BUDGET_MS=N` prints a line for each commit over `N` ms in any build, with view, layout, text and apply times and what made the frame commit, at most once a second. `El::scroll_anchor()` keeps the row at the top of a scroll viewport where it is when a commit changes the content above it, like CSS `overflow-anchor`. rune-kit's table and tree viewports and header cells no longer commit on every frame of an outer page's scroll, and a diff view's code lines no longer commit for each line the pointer crosses. `scripts/app-audit` checks for `window_layout`, layout and hover handlers without `live_only`, and instant scrolls stepped by `wake_after`. The README and the docs site's Fast apps page have a "Smooth scrolling" section.
