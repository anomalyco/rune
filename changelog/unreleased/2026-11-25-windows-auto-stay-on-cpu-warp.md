- **Windows `CpuFirst::Auto` stays on `CpuPainter` on WARP-only machines:** on GPU-less Windows machines whose only DXGI/wgpu adapters are software ones (WARP) with `WGPU_ADAPTER_NAME` unset, opaque windows under `CpuFirst::Auto` now stay on `CpuPainter` instead of handing over to WARP at idle (saving ~63 MiB private memory and avoiding 12.5×–343× slower WARP frames), and an opaque second window ignores a pooled WARP device from a transparent window or overlay. If a mid-session frame later uses a GPU-only feature (under either `Auto` on WARP-only machines or `Only`), WARP builds off the UI thread (~1.5 s on first effect shader compile) with zero quiet-wait deferral while degradable features paint live without their GPU-only modifier (`El::blur` unblurred, `El::rotate` unrotated, nested `El::backdrop_blur` unblurred, compositor effect and native-surface slots blank, linear blending in sRGB) instead of freezing the window; `FontSmoothing::Slug`, Slug outline glyphs, unknown instance kinds, and mismatched targets keep the previous frame, and frame 1 stays cloaked until the GPU draws it. Hardware GPU machines, transparent windows, overlays, pinned `WGPU_ADAPTER_NAME` adapters, `CpuFirst::Off`, and Linux/macOS/iOS/web startup are unchanged; restore immediate WARP handover on GPU-less Windows with `App::cpu_first(CpuFirst::Off)`, `RUNE_CPU_FIRST=0`, or `WGPU_ADAPTER_NAME`.
