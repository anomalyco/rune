- **Linux: a window's first frame is drawn on the CPU and on screen before any GPU exists, live from that frame; the GPU takes the window over when it's ready.** An opaque window opens with no Vulkan instance (which loads every installed driver), device or pipeline: the CPU renderer paints the frame into a `wl_shm` buffer attached to winit's `wl_surface` (Wayland), or into a buffer put to the window as an image (X11, 24-bit true-colour visuals), and the window comes on screen with it. Input, hover and motion run as on the GPU. After that frame a thread makes the device and renderer (`warm_gpu`'s slot); when they're there the UI thread makes the Vulkan surface and swap chain on the same surface or window and draws the next frame with the GPU. The display shows the CPU's last frame until that one presents, and from the moment the swap chain exists the CPU sends nothing. A Wayland client-side frame's rounded bottom corners are cleared on the CPU as the GPU pass clears them. A GPU that can't be made leaves the window on the CPU, fully live (three tries, 30 s apart). Under headless weston, sway and Xvfb with software Vulkan (llvmpipe), `examples/launch-floor` shell: first frame 230,132 → 11,206 µs from `main` (weston), 226,064 → 9,892 (sway), 236,451 → 33,352 (Xvfb, 20,572 of it winit's X11 event loop); the GPU's first frame differs from the CPU's last in 0 of 1,024,000 pixels (`RUNE_CPU_BOOT_DRIFT=1`), and screenshots across the hand-over show one picture. Not measured on a real GPU or a real desktop. `RUNE_CPU_FIRST=0` turns it off, `RUNE_CPU_FIRST=only` never starts the GPU; a window opens on the GPU as before when it's transparent, when another window already has a GPU, or when the display takes no CPU frames.
