- **A handler can read where one element is laid out or drawn.** `Tx::read_layout(key, f)` gives the element's laid-out rect in window points after scrolling, and `Tx::read_presented(key, f)` gives its rect and opacity as the last frame drew it, the handler-side `Runtime::presented`. Both take a key or key path and run `f` after the handler, before its commit, like `Tx::element_at`, so a handler that removes rows can still read where they stood and start an effect from there without keeping them for an extra frame.
