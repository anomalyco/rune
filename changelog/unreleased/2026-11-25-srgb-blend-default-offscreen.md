- **Breaking (pixels, no compile error) — sRGB blending is now the default off screen too:** `Runtime::new` / `Runtime::with_text` now default to `srgb_blend: true`, `OFFSCREEN_FORMAT` changed from `wgpu::TextureFormat::Rgba8UnormSrgb` to `Rgba8Unorm` (adding `OFFSCREEN_FORMAT_LINEAR = Rgba8UnormSrgb`, `Offscreen::format()`, and `SurfaceRenderer::srgb_blend()`), and `Renderer` / `SurfaceRenderer` default `srgb_blend` to `true` for 8-bit non-sRGB targets (`Rgba8Unorm`, `Bgra8Unorm`) while keeping `*Srgb` and HDR `Rgba16Float` targets linear. Apps using `App` windows, overlays, or `App` headless `--snap` see no change; standalone callers driving `Runtime`, `Renderer`, `SurfaceRenderer`, or `Offscreen::new` directly now match `App` windows within 1 LSB instead of blending in linear light (translucent fills and shadows become darker by ~25–34 LSB on mid-tones, e.g. black at 19% alpha over `#F7F8FA` moves from `225, 226, 228` to `200, 201, 203`, and code branching `if srgb { OFFSCREEN_FORMAT.remove_srgb_suffix() } else { OFFSCREEN_FORMAT }` silently selects `Rgba8Unorm` in the `else` branch). To restore linear-light blending off screen, use `OFFSCREEN_FORMAT_LINEAR` in the linear branch and opt in explicitly: `rt.set_srgb_blend(false); let mut renderer = Renderer::new(&gpu.device, OFFSCREEN_FORMAT_LINEAR); renderer.set_srgb_blend(false); let target = Offscreen::with_format(&gpu.device, w, h, OFFSCREEN_FORMAT_LINEAR);` (and `surfaces.set_srgb_blend(false)` for standalone `SurfaceRenderer`).
