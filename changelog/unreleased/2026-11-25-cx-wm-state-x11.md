- **`DecorationMode`, `TiledEdges`, `WindowActions`, `WindowManagerState`, `Cx::decoration_mode`, `Cx::tiled_edges`, `Cx::window_actions`, and `Runtime::set_window_manager_state`: reactive window-manager state with X11 EWMH/`_GTK_EDGE_CONSTRAINTS` backend.** Views can read confirmed decoration mode (`Unknown` / `Server` / `Client`), per-edge tiled state (`Option<TiledEdges>`), and allowed window actions (`window_menu`, `maximize`, `minimize`, `fullscreen`, `close`, each `Option<bool>`), preserving explicit unknown values wherever a platform or window manager does not report them. Packed into unused bits of `chrome_bits` so reading views and `memo` closures rebuild automatically on change while views that never read them do no extra work. On X11, Rune reads `_NET_FRAME_EXTENTS`, `_GTK_EDGE_CONSTRAINTS`, per-window `_NET_WM_ALLOWED_ACTIONS`, and root `_NET_SUPPORTED` in pipelined `x11rb` queries on chrome sync and window move (zero X11 round trips on ordinary redraws); macOS, Windows, web, and Wayland (pending follow-up winit support) honestly report unknown values.
