- **Windows: a mouse button acts at the point its message carries.** winit reports a press without its point, so Rune used the last move's, and with none (Windows' leave tracking ends the pointer when no real cursor is over the window, as with messages an automation driver posts) it read the system cursor, which is elsewhere or, on a desktop no one sees, unreadable: the press was dropped and no drag began. `platform::win32::press_point` records each button message's own point while winit handles it.
