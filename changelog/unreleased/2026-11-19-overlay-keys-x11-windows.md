- **`KeyPolicy::OnDemand` overlays take the keyboard on X11 and Windows too.** As on macOS and layer-shell Wayland, `OverlayHandle::request_keys` on a shown overlay, or a click on it, gives it the keys, and `capabilities().nonactivating_keys` reports `Supported` (it was `Unsupported`, and the keys went to the app in front). On X11 the override-redirect window sets the input focus itself; on Windows the window is made without `WS_EX_NOACTIVATE`, and `request_keys` takes the foreground only when Windows lets the process, as an activating window show does. An overlay's context menu on Windows hands the foreground back after, whatever its policy. Showing alone still never takes focus, and `KeyPolicy::None` overlays behave as before; every backend now reports `nonactivating_keys` by policy, so a macOS `KeyPolicy::None` overlay reports `Unsupported` (it reported `Supported`).
