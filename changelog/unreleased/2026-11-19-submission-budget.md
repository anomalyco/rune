- **Windows, debug builds and tests: a GPU submission that holds the GPU past 250 ms is reported as it happens.** Windows resets a GPU whose one submission runs 2 s, and an AMD GPU preempts nothing smaller than a submission, so work that a fast GPU finishes at once can reset a slow one. The vendored wgpu-hal times each D3D12 submission on the GPU, with timestamps of its own around it, so a queue wait before it or another device's work ahead of it doesn't count; `rune_gpu::budget` prints any past `BUDGET`. In Rune's tests (and crates that turn on `test-strict`) the test whose GPU it was fails when that GPU drops, on its own thread, by name; in a debug app it is logged. A queue without timestamps isn't timed and says so once. Release builds compile none of it.
